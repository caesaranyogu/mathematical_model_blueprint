## 1. pathlib Fundamentals

`pathlib` builds file paths so you never hardcode `C:\Users\caesanyo\...` anywhere.

| Environment | What to use | Why |
|---|---|---|
| `.py` script | `Path(__file__).parent` | `__file__` = the script currently running |
| Jupyter notebook | `Path.cwd()` | Notebooks don't have a `__file__` — use current working directory |
| SageMaker notebook | `Path.cwd()` | Returns `/home/sagemaker-user` |

**The `/` operator** joins path segments. The left side must be a `Path` object:

```python
# ✅ Correct — Path object on the left
Path.cwd() / "data" / "file.xlsx"

# ❌ Wrong — two plain strings can't use /
"data" / "file.xlsx"
```

## 2. Common Mistakes and Fixes

### Mistake 1: Using `__file__` in a Jupyter Notebook

```python
Base = Path(__file__).parent.parent
df = pd.read_excel(Base / "data" / "shift_readiness_sample.xlsx")
```

**Error:**
```
NameError: name '__file__' is not defined
```

**Why:** `__file__` only exists in `.py` script files. Jupyter notebooks run in a kernel, not from a file path.

**Fix:**
```python
df = pd.read_excel(Path.cwd() / "data" / "shift_readiness_sample.xlsx")
```

---

### Mistake 2: Putting the path inside `Path.cwd()` parentheses

```python
df = pd.read_excel(Path.cwd(data/shift_readiness_sample.xlsx))
```

**Error:**
```
NameError: name 'data' is not defined
```

**Why:** Without quotes, Python thinks `data` and `shift_readiness_sample` are variable names.

---

### Mistake 3: Using `/` between two strings

```python
df = pd.read_excel(Path.cwd("data"/"shift_readiness_sample.xlsx"))
```

**Error:**
```
TypeError: unsupported operand type(s) for /: 'str' and 'str'
```

**Why:** The `/` operator only works when the left side is a `Path` object. Two plain strings can't use `/`.

**Fix — the correct pattern:**
```python
df = pd.read_excel(Path.cwd() / "data" / "shift_readiness_sample.xlsx")
#                          ^^^ parentheses close HERE
#                              ^ THEN the / operator chains segments
#                                 each segment is a quoted string
```

```python

```

## 4. CSV ParserError — Debugging a Multi-Section File

```python
df = pd.read_csv(Path.cwd() / "data" / "caesar_shadow_report.csv")
```

**Error:**
```
ParserError: Error tokenizing data. C error: Expected 2 fields in line 25, saw 4
```

**Why:** The file has multiple sections with different column counts. Pandas assumed 2 columns from the top, then hit line 24 which has 4 columns.

### Step 1: Read the raw file first

Before parsing with pandas, look at the raw text to see what's actually in there:

```python
file_path = Path.cwd() / "data" / "caesar_shadow_report.csv"

with open(file_path, "r") as f:
    for i, line in enumerate(f):
        print(f"Line {i:>3}: {line.rstrip()}")
        if i >= 30:
            break
```

**What each piece does:**

| Code | Meaning |
|---|---|
| `open(file_path, "r")` | Open the file in read mode |
| `as f` | Nickname for the opened file |
| `with` | Auto-closes the file when done |
| `enumerate(f)` | Loop through lines AND count them (i=0, i=1, i=2...) |
| `f"Line {i:>3}"` | Print line number, right-aligned, 3 chars wide |
| `line.rstrip()` | Strip invisible whitespace/newlines from the end |
| `if i >= 30: break` | Stop after 30 lines — just enough to see the problem |


### Step 2: Map the file anatomy

| Lines | Section | Columns |
|---|---|---|
| 0–4 | Metadata (name, date, rank) | 2 |
| 7–12 | Shadowed tickets summary | 2 |
| 15–21 | Mentored tickets summary | 2 |
| 24+ | Shadow log detail | 4 |

### Step 3: Read each section separately

**Section 1 — Metadata:**
```python
metadata = pd.read_csv(
    file_path,
    header=None,
    names=["Key", "Value"],
    nrows=5
)
```

**Section 2 — Shadowed Tickets:**
```python
shadowed = pd.read_csv(
    file_path,
    skiprows=7,
    nrows=5
)
```

**Section 3 — Mentored Tickets:**
```python
mentored = pd.read_csv(
    file_path,
    skiprows=15,
    nrows=6
)
```

**Section 4 — Shadow Log Detail:**
```python
shadow_log = pd.read_csv(
    file_path,
    skiprows=24,
    names=["Date", "Type", "Who I Shadowed", "Notes"],
    quotechar='"',
    on_bad_lines='warn'
)
```

## 5. pd.read_csv() Parameter Cheat Sheet

| Parameter | What It Does | When to Use |
|---|---|---|
| `skiprows=N` | Skip the first N lines | File has headers/metadata before the data |
| `nrows=N` | Only read N rows of data | File has multiple sections, stop before the next one |
| `header=None` | Don't treat the first row as column names | No header row, or you're naming columns yourself |
| `names=[...]` | Use these as column names | You want to define your own headers |
| `quotechar='"'` | Text inside quotes is ONE cell, even with commas | Cells contain commas (e.g. "Atlanta, GA") |
| `on_bad_lines='warn'` | Warn on messy lines but don't crash | File has inconsistent rows |
| `on_bad_lines='skip'` | Silently skip bad lines | Quick and dirty — just get what works |

## 6. Error Quick-Reference

| Error | Root Cause | Fix |
|---|---|---|
| `NameError: __file__ is not defined` | Used `__file__` in Jupyter notebook | Use `Path.cwd()` instead |
| `NameError: name 'data' is not defined` | Forgot quotes around path strings | `"data"` not `data` |
| `TypeError: unsupported operand type(s) for /: 'str' and 'str'` | Used `/` between two plain strings | Left side must be a `Path` object: `Path.cwd() / "data"` |
| `ImportError: Missing optional dependency 'openpyxl'` | pandas needs openpyxl for .xlsx files | `!pip install openpyxl` |
| `ParserError: Expected N fields in line X, saw M` | Inconsistent column counts across rows | Read raw file with `open()`, then use `skiprows`/`nrows` per section |

## 8. Context: What Skill Is This?

This is **Data Ingestion** — the first phase of **ETL (Extract, Transform, Load)**:

| ETL Phase | What Happened in This Session |
|---|---|
| **Extract** | Found files in SageMaker, built paths with `pathlib`, read with `pd.read_excel()` and `pd.read_csv()` |
| **Transform** | Diagnosed multi-section CSV, parsed each section with `skiprows`/`nrows`, handled quoted commas |
| **Load** | Loaded clean DataFrames into pandas for analysis |

This is the plumbing that makes everything else work. A lot of people can build a model — the ones who can reliably get the data into the model from messy real-world sources are the ones companies fight over.
