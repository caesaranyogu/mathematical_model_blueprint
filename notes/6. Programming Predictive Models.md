
# Programming Predictive Models

Building a predictive model from raw data to predictions using linear algebra and Python. No black boxes. Every matrix operation done by hand.


## The Pipeline

CSV → Pandas loads it → .values hands off to NumPy → Build matrix → Transpose → XᵀX (self-correlation) → (XᵀX)⁻¹ (untangle) → Xᵀy (feature-outcome correlation) → Weights → Predictions


## Pandas vs NumPy

Pandas is the filing cabinet with labeled folders. NumPy is the calculator. Pandas loads, labels, and filters. NumPy does the math. The bridge between them is `.values` which strips the labels and gives raw numbers.

```python
import pandas as pd
import numpy as np

data = pd.read_csv("data.csv")                    # Pandas: load labeled spreadsheet
X = data[["feature_1", "feature_2"]].values        # .values: handoff to NumPy
y = data[["target"]].values                        # now raw number arrays for math
```


## CSV Rules

First row is column headers. Every other row is one observation. Every cell is a number — no blanks, no text, no "N/A". Column names must exactly match what the code expects. Validate before modeling:

```python
print(data.isnull().sum())       # check for blanks
print(data.dtypes)               # check for text in number columns
print(data.describe().round(1))  # sanity check ranges
```


## The Matrix

A matrix is a grid of numbers. Rows are observations (the things you measured). Columns are features (what you measured about them).

```python
E = np.array([
    [10, 4, 2],
    [7, 3, 3],
    [15, 5, 2],
    [3, 0, 4],
    [30, 3, 0]
])

print(f"The shape of the matrix is {E.shape}")
print(f"That means this matrix has {E.shape[0]} observations and {E.shape[1]} features")
# (5, 3) → 5 observations, 3 features

print(f"Observation 3, Feature 2: {E[2, 1]}")  # → 5
```


## The Transpose

Transposing flips rows and columns so features can be compared to each other across all observations. If X is 5×3, Xᵀ is 3×5. The same value lives in both matrices at swapped positions.

```python
E_T = E.T

print(f"Original: {E.shape}")      # (5, 3)
print(f"Transposed: {E_T.shape}")  # (3, 5)
print(f"E[2,1] = {E[2,1]} and E_T[1,2] = {E_T[1,2]}")  # Both → 5
```

Transposing is important so that we can check the correlation of each feature to other features in our matrix. Without the transpose, the dimensions don't line up for that multiplication.


## XᵀX — Feature Self-Correlation

Multiplying the transpose by the original reveals how features relate to each other. Diagonal values show each feature's spread. Off-diagonal values show how pairs move together. Large off-diagonal values mean those features are tangled — the model needs to untangle them to give each one honest credit.

```python
XtX = E.T.dot(E)   # shape: (3, 3) — features × features
```


## The Dot Product

The dot product multiplies pairs and sums them into one value. Prediction IS a dot product — each feature times its weight, all added up. The Hadamard product (element-wise) multiplies without summing — used for masking and gating, not prediction.

```python
a = np.array([2, 3, 4])
b = np.array([5, 6, 7])

a.dot(b)   # dot product: (2×5)+(3×6)+(4×7) = 56 → one number (blender)
a * b      # Hadamard:    [10, 18, 28]       → same shape (volume knobs)
```


## The Design Matrix

Before running the normal equation, add a column of 1s to the left of the feature matrix. This column represents the bias (intercept) — the baseline prediction when all features are zero.

```python
def assemble_design_matrix(features):
    n = features.shape[0]
    return np.append(np.ones((n, 1)), features, axis=1)
```


## The Normal Equation — Finding True Weights

w = (XᵀX)⁻¹ · Xᵀy

XᵀX captures how features relate to each other. The inverse (XᵀX)⁻¹ untangles the overlaps so correlated features don't get double credit. Xᵀy captures how each feature relates to the outcome. Multiplying them together gives the true, untangled weight for each feature.

```python
def OLS(features, y):
    X = assemble_design_matrix(features)
    return np.linalg.inv(X.T.dot(X)).dot(X.T.dot(y))

def predict(w, features):
    X = assemble_design_matrix(features)
    return X.dot(w)
```


## Train/Test Split

Never test on training data. That tests memorization, not understanding. Split the data — 75% to learn from, 25% to evaluate on. random_state locks the shuffle so results are reproducible.

```python
from sklearn.model_selection import train_test_split
from sklearn.metrics import r2_score, mean_squared_error

data_train, data_test = train_test_split(data, test_size=0.25, random_state=42)

X_train = data_train[feature_columns].values
y_train = data_train[target_column].values
X_test = data_test[feature_columns].values
y_test = data_test[target_column].values
```


## Train → Predict → Evaluate

```python
weights = OLS(X_train, y_train)
y_hat_test = predict(weights, X_test)

r2 = r2_score(y_test, y_hat_test)
rmse = mean_squared_error(y_test, y_hat_test) ** 0.5

print(f"R²: {r2:.3f} — explains {r2*100:.1f}% of variation")
print(f"RMSE: {rmse:.1f} — average error in original units")
```

R² is the percentage of outcome variation the model explains. RMSE is the average prediction error in the same units as the target. The gap between train R² and test R² reveals overfitting — if the model scores much higher on training data, it memorized instead of learned.


## Reading the Weights

Each weight tells you how much that feature moves the prediction. Negative weights reduce the target. Positive weights increase it.

```python
feature_names = ["bias"] + feature_columns
for i, name in enumerate(feature_names):
    w = weights[i][0]
    direction = "REDUCES" if w < 0 else "INCREASES"
    print(f"  {name:<30} {w:>+9.4f}  ({direction} target)")
```


## Feature Importance

Raw weights can be misleading if features are on different scales. Standardize first (subtract mean, divide by standard deviation) so every feature has the same spread. Then the absolute weight is a fair comparison of importance.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
weights_scaled = OLS(X_train_scaled, y_train)

importance = [(name, abs(weights_scaled[i+1][0]))
              for i, name in enumerate(feature_columns)]
importance.sort(key=lambda x: x[1], reverse=True)

for rank, (name, w) in enumerate(importance, 1):
    print(f"#{rank} {name}: {w:.4f}")
```


## Predicting New Observations

```python
new_observation = np.array([[20, 35, 3, 8, 50, 1]])
prediction = predict(weights, new_observation)
print(f"Predicted: {prediction[0][0]:.0f}")
```


## Quick Reference

Concept | One-Liner
--- | ---
Matrix | Grid of numbers. Rows = observations. Columns = features.
Transpose | Flip rows ↔ columns so features face each other.
Dot Product | Multiply + sum. This IS prediction.
Hadamard | Multiply element-wise. This IS gating/masking.
XᵀX | How features relate to each other across all data.
(XᵀX)⁻¹ | Untangle correlated features. Give each one honest credit.
Xᵀy | How each feature relates to the outcome.
Normal Equation | w = (XᵀX)⁻¹Xᵀy — true weights in one shot.
Design Matrix | Feature matrix with a column of 1s prepended for bias.
R² | Percentage of outcome variation the model explains.
RMSE | Average prediction error in original units.
Train/Test Split | Never test on training data. That tests memorization.
Standardization | Subtract mean, divide by std. Makes feature weights comparable.
